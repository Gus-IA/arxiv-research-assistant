# 📚 arXiv Research Assistant

An advanced RAG system that answers questions about recent scientific papers from arXiv.
It combines hybrid search (vector + keyword) with an optional cross-encoder re-ranker, and every answer cites the excerpts it comes from.

---

## 🎯 Problem

Keeping up with new research is hard: arXiv publishes hundreds of papers a day, and reading them to find what is relevant to a question takes hours.
This project indexes recent papers and lets you ask questions in natural language. Each claim in the answer points to the excerpt it was taken from, so it can be checked against the source paper.

---

## 🏗️ Architecture

```
arXiv API → download PDFs → extract text → chunks (1000 chars, 200 overlap)
    → embeddings (all-MiniLM-L6-v2) → PostgreSQL + PGVector

Question → retrieval (vector | keyword | hybrid | hybrid + re-rank)
    → top-k excerpts → LLM (Groq) with numbered excerpts
    → answer with citations [n] → only the cited papers are shown
```

**Design decisions**
- **Two tables** (`papers`, `chunks`): metadata used for filters (category, date) lives in `papers`; the searchable text and its vector live in `chunks`.
- **Hybrid search** fuses the vector and keyword rankings with Reciprocal Rank Fusion (RRF).
- **Re-ranking** with a cross-encoder (`ms-marco-MiniLM-L-6-v2`) is optional and selectable in the UI.
- **Only cited sources are shown.** If the model says the excerpts do not contain the answer, no papers are listed.
- **Relevance threshold** on the re-ranker score removes clearly irrelevant excerpts.

---

## 🛠️ Stack

| Component | Tool |
|---|---|
| Data source | arXiv (categories cs.RO, cs.LG, cs.CL) |
| Vector DB | PostgreSQL 17 + PGVector |
| Embeddings | `sentence-transformers/all-MiniLM-L6-v2` (local) |
| Re-ranker | `cross-encoder/ms-marco-MiniLM-L-6-v2` (local) |
| LLM | Groq API (`openai/gpt-oss-20b`) |
| UI | Streamlit |
| Containers | Docker Compose |

## 📊 Retrieval evaluation

For each paper, one question was generated by an LLM from a random excerpt of the paper body (not the abstract). A method scores a hit if the exact excerpt, or its paper, appears in the top 5 results. 51 questions in total.

| Method | Paper hit@5 | Chunk hit@5 | MRR |
|---|---|---|---|
| vector | 0.961 | 0.804 | 0.570 |
| keyword | 0.980 | 0.941 | 0.784 |
| hybrid | 0.980 | 0.902 | 0.755 |
| hybrid + rerank | 0.980 | 0.882 | 0.734 |

**Conclusions**
- Vector search is clearly the weakest on this question set.
- Keyword, hybrid and hybrid + rerank differ by 1 to 3 questions out of 51, which is within the noise for a sample this small.
- Hybrid is used by default because it does not depend on the user reusing the exact vocabulary of the paper, but the evaluation does not prove it is better than keyword.
- The re-ranker did not improve results on this dataset.

**Limitations**
- Small sample (51 questions, 55 papers).
- Questions are written from the same text they target, which favors keyword search (lexical overlap). A paraphrased question set would be a fairer test for semantic search.
- A first version of the evaluation, with questions generated from abstracts, scored 1.000 for every method. It was too easy (the abstract is repeated in the paper text), so it was replaced.
- The LLM generation step (prompts, answer faithfulness) has not been formally evaluated.

## 🚀 How to run

### 1. Clone and configure
```bash
git clone https://github.com/Gus-IA/arxiv-research-assistant.git
cd arxiv-research-assistant
cp .env.example .env
# Edit .env: set GROQ_API_KEY and a PostgreSQL password
```

### 2. Start the services
```bash
docker compose up -d --build
```

### 3. Ingest papers
```bash
docker compose run --rm app python src/ingest.py
```
Downloads the latest papers of each category, extracts the text, creates the embeddings and stores them. Papers already indexed are skipped, so it can be re-run safely.
Note: the papers fetched depend on the day you run it, because arXiv is queried by submission date.

### 4. Open the app
```
http://localhost:8501
```

### 5. (Optional) Run the evaluation
```bash
docker compose run --rm app python notebooks/generate_questions.py
docker compose run --rm app python notebooks/evaluate_retrieval.py
```
Generate the questions after ingesting: they reference chunk ids from your database.

## 🔑 Environment variables

```env
POSTGRES_DB=arxiv
POSTGRES_USER=arxivuser
POSTGRES_PASSWORD=change_me
POSTGRES_HOST=localhost
POSTGRES_PORT=5433

GROQ_API_KEY=your_groq_api_key_here
LLM_MODEL=openai/gpt-oss-20b
```

Inside Docker, the app connects to the database as `postgres:5432` automatically.
